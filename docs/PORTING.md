# Как устроен перенос с Windows

Windows-версия запускает `winws` (nfqws1) с опциями `--dpi-desync-*`. В zapret2 их нет: `nfqws2` только разбирает пакеты, а воздействие на трафик описывается функциями Lua через `--lua-desync`. Поэтому стратегии не копируются, а переводятся скриптом [tools/bat2conf.py](../tools/bat2conf.py). Правила ниже проверены по исходникам nfqws1 (`nfq/desync.c`, `nfq/nfqws.c`, `nfq/params.c`).

Перевести заново, например после обновления стратегий Flowseal: положить новые `.bat` в `tools/bat/`, выполнить `python3 tools/bat2conf.py` и обновить `FLOWSEAL` в `VERSION`. Опция, которой скрипт не знает, вызывает ошибку: её нужно сопоставить вручную, а не потерять молча.

## Соответствие опций

| winws | nfqws2 | Примечание |
| :--- | :--- | :--- |
| `--wf-tcp`, `--wf-udp` | правила файрвола, `PORTS_TCP` и `PORTS_UDP` в `.conf` | Пересекающиеся диапазоны сливаются, иначе их не примут nftables |
| `--dpi-desync=fake` | `fake:blob=...` | Отдельный экземпляр на каждый тип данных и каждый фейк |
| `--dpi-desync=multisplit` | `multisplit` | |
| `--dpi-desync=multidisorder` | `multidisorder_legacy` | Порядок сегментов как в nfqws1. У `multidisorder` он другой |
| `--dpi-desync=fakedsplit` | `fakedsplit` | |
| `--dpi-desync=hostfakesplit` | `hostfakesplit` | |
| `--dpi-desync-hostfakesplit-mod=altorder=1` | `hostfakesplit_alt` | **Дописано:** в zapret2 такого режима нет, см. ниже |
| `--dpi-desync=syndata` | `syndata` | |
| `--dpi-desync-repeats=N` | `repeats=N` | Только у пакетов-обманок. Настоящие сегменты nfqws1 шлёт по одному разу |
| `--dpi-desync-fooling=ts` | `tcp_ts=-600000` | Значение по умолчанию из nfqws1 |
| `--dpi-desync-fooling=badseq` | `tcp_seq=N:tcp_ack=-66000` | badseq в nfqws1 меняет и seq, и ack. N из `--dpi-desync-badseq-increment`, по умолчанию -10000 |
| `--dpi-desync-fooling=md5sig` | `tcp_md5` | |
| `--dpi-desync-split-pos` | `pos=` | По умолчанию 2, как в nfqws1 |
| `--dpi-desync-split-seqovl`, `-pattern` | `seqovl=`, `seqovl_pattern=` | |
| `--dpi-desync-fakedsplit-pattern` | `pattern=` | |
| `--dpi-desync-fake-tls=!` | `blob=fake_default_tls` | |
| `--dpi-desync-fake-tls-mod` | `tls_mod=` | Действует на последний фейк и все следующие, как `tls_mod_last` в nfqws1 |
| без `--dpi-desync-fake-tls` | `fake_default_tls:tls_mod=rnd,rndsni,dupsid` | Значение по умолчанию из nfqws1 |
| `--ip-id=zero` | `ip_id=zero` | У каждого экземпляра профиля |
| `--dpi-desync-any-protocol=1` | `--payload=all` и `payload=~empty,...` | См. ниже |
| `--dpi-desync-cutoff=nN` | `--out-range=<dN-1` для TCP, `<nN` для UDP | См. ниже |

У всех TCP-экземпляров стоит `tcp_ts_up`. nfqws1 при сборке сегмента всегда ставил опцию timestamp первой, а без этой опции nfqws2 оставляет порядок операционной системы. В руководстве zapret2 описан случай, когда это меняет поведение сервера.

## Места, где прямой перевод был бы ошибкой

**Счётчик пакетов в `cutoff`.** Фильтр WinDivert не перехватывает пустые ACK (`DIVERT_TCP_NOT_EMPTY`), поэтому в winws пакеты считаются так: SYN = 1, первые данные = 2. На Linux nfqws2 видит всё: SYN = 1, ACK = 2, первые данные = 3. Перенос `n3` как есть отрезал бы первый пакет с данными. Поэтому для TCP используется счётчик пакетов с данными: `n3` становится `<d2`, то есть обрабатывается только первый пакет данных. Для UDP счётчики совпадают.

**`any-protocol`.** В nfqws2 фильтр `--payload=all` пропускает и пустые пакеты, а внутренняя проверка Lua по умолчанию отсекает неизвестные. Поэтому нужны оба условия: `--payload=all` и `payload=~empty,<типы со своими фейками>`. nfqws2 распознаёт больше протоколов, чем nfqws1 (dns, dtls, mtproto и другие), и для совпадения с оригиналом они считаются неизвестными.

**Фейки по умолчанию для UDP.** С `--dpi-desync=fake` nfqws1 обрабатывает и протоколы, для которых фейк не задан: QUIC получает 620 байт с `0x40` в начале, а WireGuard (только initiation), DHT, Discord и STUN получают 64 нуля. Эти варианты тоже переведены, если профиль их допускает. Профиль с хостлистом допускает только QUIC, остальные протоколы не содержат имени хоста.

**Код ошибки curl 35 в тестах.** В Windows-скрипте он значит «не поддерживается», потому что так schannel сообщает о версии TLS. У curl с OpenSSL код 35 появляется ещё и при обрыве рукопожатия, а это типичная блокировка. Поэтому `UNSUP` здесь определяется по тексту ошибки, а обрыв считается `ERROR`.

**syndata и conntrack.** `syndata` заменяет исходный SYN своим. Если вывести его из conntrack, как все остальные созданные пакеты, у соединения не появится записи, правило `ct original packets` не сработает и `nfqws2` не получит данные. Поэтому SYN остаётся под отслеживанием, см. `nft_up` в `lib/engine.sh`.

**TCP timestamps и `be_liberal`.** Стратегии с `ts` требуют включённых timestamps: их включает `tcp_timestamps_enable`, аналог `:tcp_enable` из `service.bat`. На время работы также включается `nf_conntrack_tcp_be_liberal`, иначе conntrack отбрасывал бы ответы на пакеты с `seqovl`. При выключении обхода значение возвращается.

## Что дописано

**`hostfakesplit_alt`** в [lua/zapret-cap.lua](../lua/zapret-cap.lua) реализует `altorder=1` из nfqws1: часть до имени хоста, поддельное имя, часть после имени, настоящее имя. Второй подделки нет. Файлы движка в `core/` не менялись.

## Что отличается от Windows

**Сборка ClientHello.** Если ClientHello занимает несколько сегментов, nfqws1 делит каждый сегмент отдельно, а nfqws2 сначала собирает его целиком и потом делит. Это свойство движка, повлиять на него из стратегии нельзя.

**Первые N пакетов.** winws получает весь поток, а здесь файрвол передаёт только начало соединения: 20 исходящих TCP и 12 UDP. Этого хватает, потому что стратегии работают с началом соединения. Значения меняются переменными `ZAPRET_PKT_*`.

**`fakedsplit` со списком позиций.** nfqws1 выбирает первый относительный маркер, потом абсолютный, а nfqws2 принимает одну позицию. Сейчас ни одна стратегия так не делает. Если такое появится, скрипт перевода остановится с ошибкой.

## Перенос service.bat

| service.bat | Здесь |
| :--- | :--- |
| Install Service | `zapret use`, пункт 4. Служба systemd `zapret-cap` |
| Remove Services | `zapret stop`, пункт 5 |
| Check Status | `zapret status`, пункт 6 |
| Game Filter | `zapret game`, `zapret game-ports`, пункт 11. Тот же файл `utils/game_filter.enabled` и порт-заглушка 12 |
| IPSet Filter | `zapret ipset`, пункт 12. Те же режимы и то же значение-заглушка |
| Auto-Update Check | `zapret update-check on\|off`, пункт 14 |
| Replace active fakes | `zapret fakes`, пункт 13 |
| Update IPSet List | `zapret ipset update`, пункт 15 |
| Update Hosts File | `zapret hosts`, пункт 16. Записывает блок в `/etc/hosts` с подтверждением и резервной копией |
| Check for Updates | `zapret update-check`, пункт 17 |
| Run Diagnostics | `zapret diag`, пункт 18 |
| Run Tests | `zapret test`, пункт 1 |

Проверки из диагностики, которые имеют смысл только на Windows, не перенесены: Base Filtering Engine, Killer, Intel Connectivity, Check Point, SmartByte, OneDrive и служба WinDivert. Вместо них проверяются модуль ядра `nfnetlink_queue`, наличие nftables или iptables и правила файрвола, оставшиеся без `nfqws2`.

Новое по сравнению с Windows: `zapret next`, `zapret auto` и добавление доменов. Тесты не требуют снимать службу вручную: утилита сама останавливает её на время теста и потом возвращает.

## Окно приложения

Окно написано на Python, GTK 4 и libadwaita ([gui/](../gui/)) и не содержит логики обхода: каждая кнопка вызывает те же команды утилиты, что и терминал. Для этого у утилиты есть команды с выводом для программы ([lib/api.sh](../lib/api.sh)): `zapret state`, `zapret list --tsv`, `zapret fakes list`, а `--machine` у тестов добавляет строки прогресса `@progress` и `@result`.

**Права.** Окно работает от обычного пользователя. Чтение обходится без root: `proc_exe` читает командную строку процесса, потому что ссылка `/proc/PID/exe` чужого процесса без root недоступна. Изменения идут через `pkexec`, а правило polkit ([data/](../data/)) просит пароль один раз за несколько минут.

**Остановка теста.** Обычный пользователь не может послать сигнал тесту, запущенному от root. Поэтому тест записывает свой номер в `/run/zapret-cap/test.pid`, а окно вызывает `zapret test-cancel`. Если окно закрылось или упало, тест получает SIGPIPE, возвращает прежний обход и завершается.

**Установка.** `install.sh` и пакет `.deb` кладут в систему значок, запись для меню приложений, правило polkit и карточку для центра приложений. Пакет `.deb` собирает движок при установке: один файл подходит для разных версий Debian, Ubuntu и Mint и для разных процессоров, зато в зависимостях остаются компилятор и заголовки.

## Как это проверено

[tests/sandbox-test.sh](../tests/sandbox-test.sh) работает без прав администратора в отдельных пространствах имён Linux и не затрагивает сеть компьютера. Внутри запускаются настоящие `nfqws2` и `nftables`, а сайты изображает локальный HTTPS-сервер. Для запуска нужны `/etc/subuid` и `newuidmap`.

Тест показывает, что утилита работает и все стратегии запускаются, не ломая соединение. **Обходит ли стратегия настоящий DPI, в такой среде проверить нельзя:** это видно только на реальной сети провайдера.

Пакеты конкретной стратегии можно посмотреть так:

```bash
SANDBOX_WIRE="ALT13" tests/sandbox-test.sh
```

[tests/gui-test.sh](../tests/gui-test.sh) запускает настоящее окно в том же изолированном окружении и нажимает его кнопки: включение и выключение, смена стратегии, проверка с остановкой, автоподбор, сайты, все настройки, диагностика, закрытие окна во время проверки. Результат сверяется с утилитой. Окно рисуется через Broadway, а снимки сохраняются в указанную папку. Настоящее окно пароля и работа на настоящем рабочем столе так не проверяются.

[tests/install-test.sh](../tests/install-test.sh) подменяет системные папки наложением и проверяет `install.sh`, `uninstall.sh`, а также установку, обновление и удаление пакета настоящим `dpkg`. Настройки при обновлении должны сохраняться. `systemctl` там заменён заглушкой, которая записывает вызовы.
